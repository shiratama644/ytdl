# 計画書テンプレート (新規計画書は本形式で作成する)

> **形式の出典**: Qiita「Claude Code／Codex に中〜大規模開発を任せるためのタスク管理」
> <https://qiita.com/Y-Y-dev/items/d526fb7cdbe35a3f9384> (2026-08-27 ユーザー指定、dropmod 経由)。
>
> - **進捗の正本は [`AGENTS.md`](../../AGENTS.md) §5（タスク完了条件）**。計画書は個別タスクの詳細（目的・範囲・条件）を担う。
> - 各タスクの計画書は本テンプレートの §1〜§9 を必須セクションとし、§10〜§12（設計詳細・Gotchas・実績）を必要に応じて増減する。
> - 新規タスクを計画する場合、特段の指示がなければ先に [`AGENTS.md`](../../AGENTS.md) §5 の完了条件で作業を進めます。

## 7. 停止条件

次の場合は作業を停止し、変更せず報告する:
- 仕様書 (計画書・AGENT.md・skills) 同士に矛盾がある
- 計画書の変更範囲を超える変更が必要
- 破壊的変更 (既存データ・公開 API 互換性) が必要
- ユーザー判断が必要な設計論点に到達した
- 開始時点で作業ツリーに未確認の変更がある

3. コミット (Conventional Commits 形式) と push を実行
4. 証拠中心の完了報告 (結果 / テスト件数 / Git SHA / 残事項)
