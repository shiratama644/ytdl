# アーキテクチャ意思決定ログ（ADR）

本ドキュメントは、プロジェクトにおける重要な設計上の決定・採否理由を記録する ADR (Architecture Decision Records) です。
一度決定された ADR を覆す場合は、**勝手に変更せずユーザーに確認**します。

---

## ADR-001: エージェントシステム及びドキュメントシステムの導入

- **ステータス**: 承認済
- **日付**: 2026-09-06
- **背景・文脈**: AI Agent との協調開発において、コンテキスト断絶時の復旧性・品質保証・進捗管理・知見の蓄積を担保する必要がある。
- **決定内容**: `shiratama644/cod-web` の方式を踏襲し、`AGENTS.md`、`.agent/`（hooks / skills / logs）、`docs/`（arch / planning / task-list）の構造を導入した。

## ADR-002: パッケージマネージャ・ランタイムに Bun を採用

- **ステータス**: 承認済
- **日付**: 2026-09-06
- **背景・文脈**: 開発の高速性、軽量性、ネイティブ TypeScript 実行環境を確保する。
- **決定内容**: パッケージマネージャーおよびランタイムに **bun** を採用する（`bun.lock`、`bun install`、`bun run`）。
- **理由・メリット**:
  - 高速なパッケージ解決とインストール。
  - サーバーサイド TypeScript をトランスパイル不要で直接実行可能。
  - 軽量でリソース効率が高い。

## ADR-003: フロントエンドに Vite + React + TypeScript を採用（Next.js の不採用）

- **ステータス**: 承認済
- **日付**: 2026-09-06
- **背景・文脈**: サーバーのスペックが限られており、Next.js のようなヘビーな SSR フレームワークはリソース的に厳しいため。
- **決定内容**: クライアントは Vite + React + TypeScript の SPA 構成とし、静的配信および軽量プロキシサーバーと分離する。
- **理由・メリット**:
  - メモリ消費量が極めて少なく、低スペックサーバーでも快適に動作する。
  - Vite による高速な開発・ビルド体験。

## ADR-004: YouTube クライアントに youtubei.js (Innertube) を採用

- **ステータス**: 承認済
- **日付**: 2026-09-06
- **背景・文脈**: YouTube 公式 Data API はクォータ制限が厳しく、動画ストリームの直接解決ができない。
- **決定内容**: `youtubei.js` を採用し、検索・動画メタデータ・ストリーミング URL の解決・中継を行う。

---

## ADR-005: バックエンドサーバーに Hono (Bun/Node) を採用

- **ステータス**: 承認済
- **日付**: 2026-09-06
- **背景・文脈**: 軽量で高速、TypeScript 完全型安全、Web標準の Request/Response/ReadableStream API を備えたサーバーが必要。
- **決定内容**: バックエンド API およびプロキシに **Hono** を採用する。
- **理由・メリット**:
  - 極めて軽量で起動が速い。
  - Web Standard API（Fetch, ReadableStream）準拠により、Range リクエストやストリーミング中継がシンプルに実装可能。
