# エンジニアリング原則・品質基準

> コード品質、テスト基準、セキュリティ、パフォーマンスに関する原則を定義する。

## 1. ツールチェーン・ランタイム

- **ランタイム / パッケージマネージャ**: **bun**（`bun.lock`、`bun install`、`bun run`）
- **ビルド / 開発**: Vite + React + TypeScript
- **Lint / Format**: Biome
- **テストランナー**: Vitest

## 2. コーディング原則
- **KISS (Keep It Simple, Stupid)**: 不要な複雑化を避け、軽量さを最優先とする。
- **ゼロバッファ・ストリーミング**: 動画ストリームをサーバーのメモリ上に全量バッファせず、Web標準の `ReadableStream` でクライアントへ直接パイプ中継する（メモリフットプリントの最小化）。
- **Range Request の正確な処理**: クライアントからの `Range: bytes=start-end` を適切に YouTube CDN に中継し、`206 Partial Content`、`Content-Range`、`Content-Length` を正確に返却する。
- **型の安全性**: TypeScript の strict モードを適用し、`any` の安易な使用を禁止する。

## 3. テスト基準
- **単体テスト (Unit Test)**:
  - Range ヘッダーパーサー / レスポンスヘッダー構築ロジックのテスト
  - 検索クエリ整形・メタデータ変換ロジックのテスト
  - クライアント用ユーティリティ（フォーマット関数、時間表示、URL処理）のテスト
- **コンポーネントテスト**:
  - 主要 UI コンポーネントのレンダリングテスト
- **結合テスト (Mocked)**:
  - モック Innertube を用いた API ルーティングのテスト

## 4. セキュリティ & リソース管理
- **プロキシ悪用防止**: プロキシストリーミングエンドポイントは、YouTube videoId および正規 CDN ドメインのみに限定する（任意の URL へのオープンプロキシ化を禁止）。
- **接続タイムアウト・エラーハンドリング**: クライアントの切断や upstream のタイムアウト時に、速やかにストリームをキャンセルしリソースを解放する。
